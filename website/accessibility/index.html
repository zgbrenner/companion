Accessibility

COMPANION aims to remain understandable, keyboard-operable, and legible across its website and extension interfaces.

CommitmentWebsiteExtensionKnown limitsFeedback

Commitment

The project targets WCAG 2.2 AA for the public website and serious or critical accessibility-issue-free extension interfaces. Accessibility is treated as a release requirement rather than a decorative audit performed at the end.

Website measures

  • Semantic landmarks, headings, lists, buttons, links, figures, and disclosure elements.
  • A skip link and visible keyboard focus indicators.
  • Keyboard-operable navigation and product-view tabs.
  • Text alternatives for meaningful screenshots and hidden treatment for decorative marks.
  • Responsive layouts that avoid horizontal page scrolling at common mobile widths.
  • Local Atkinson Hyperlegible Next typography and strong text contrast.
  • Respect for the system’s reduced-motion preference.

Extension measures

The extension uses labeled controls, native or ARIA-compatible switches, progress semantics, live regions for status changes, keyboard-operable settings, theme-aware contrast, and local fonts selected for legibility. Automated accessibility checks and Chromium screenshots are part of the project’s test and review process.

Known limits

Provider pages are controlled by third parties, and their DOM, focus behavior, themes, and accessibility characteristics can change. An injected interface may also inherit constraints from the host page. Screenshots on this website contain visual text that is summarized in surrounding captions and alternative text rather than fully reproduced word for word.

Accessibility feedback

Report an accessibility problem through GitHub Issues or email zgbrenner@gmail.com. Include the page or extension surface, browser, assistive technology, expected behavior, and the barrier encountered. Do not include private prompts, files, passwords, cookies, or tokens.
